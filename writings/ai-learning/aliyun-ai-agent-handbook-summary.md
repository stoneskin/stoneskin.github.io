## 一、这是什么

《AI Agent Handbook》——企业级 AI Agent 全生命周期实战指南，30 章 + 2026 Agent 开发者调研报告，章节全中文，配 VitePress 阅读站。

背景：阿里云 2025 年 9 月先发了《AI 原生应用架构白皮书》，这本是续作。视角发生了转变——从"怎么快速搭出 agent"，转向三个新挑战：

1. **工程化**：把概率性的智能变成可靠的生产力
2. **规模化**：从实验到基础设施——稳定性、安全、性能、成本
3. **组织化**：把 agent 接进核心业务流程

一句话：市面上讲"怎么做 demo"的很多，讲"怎么在企业里跑起来、跑得住"的很少，这本补的是后者。

## 三、核心观点提炼

README 里承诺的几个关键 takeaway，值得先记住：

1. **选最不复杂的架构**：为任务选择复杂度最低的 agent 架构，不要过度设计
2. **分清模型问题和系统问题**：把模型能力的局限和 harness/系统的工程问题分开看
3. **长任务要可恢复**：设计长运行、可恢复的任务，有可验证的完成标准
4. **运行时控制面**：执行环境、状态、流量、权限、可观测性、成本——六个控制缺一不可
5. **改进飞轮**：从 traces、trajectories、golden 数据集、评测实验里建持续改进闭环

## 四、对 Stone 的价值分析

### 4.1 为什么"对你将来有用"

README 明确列了目标读者，其中两类就是你：

| 读者 | 对应章节 | 你的映射 |
|---|---|---|
| 架构师和平台工程师 | 架构、运行时、治理 | AI Solutions Architect 路线 |
| 技术/工程管理者 | 架构、治理、实战 | 带团队做 AI 平台（iPipeline merge conflict 团队） |

这本是你的**知识地图**：你强在企业架构和身份（Ping/OAuth），这本补的是 agent 专属的工程面——Harness、AI 网关、Trajectory→Golden 数据集飞轮、受控自进化、多智能体协同。

### 4.2 和你手里三个项目的咬合

- **thinktank**：Harness 构建模式可直接借鉴（judge 评测链）；Trajectory→Golden 数据集飞轮 = eval harness 的数据底座思路；Jev 结构化决策专题和陪审团评审的方法论相通
- **open-memex**：AI 网关、agent 可观测性、安全治理（prompt 注入、数据外泄控制）是企业版的必备件；第 13–16 章治理部分可以直接当企业版需求清单用
- **muse-agent-harness**：第 3 章 Harness 构建模式与职责划分——正是这个新 repo 要回答的问题，动手前先读这章（simplest-first：先找类似的）

### 4.3 和 FDE-Gym 的互文

昨天刚看的 FDE-Gym 论文说"会写代码 ≠ 会交付"（0.56 分）；这本手册就是"怎么把交付做好"的实战答案。两份材料一问一答：
- FDE-Gym：最后一公里有多难（量化证据）
- AI Agent Handbook：最后一公里怎么走（工程方法）

面试或给客户讲方案时，这个组合很有力："论文证明 90 分的模型真实交付只有 56 分，手册告诉我们工程上怎么补——Harness、网关、治理、飞轮。"

### 4.4 建议阅读顺序

1. **实战案例**（25–29 章）：先有体感，知道生产环境长什么样
2. **构建**（3–6 章）：动手马上用得上，thinktank/harness 直接借鉴
3. **治理**（13–16 章）：企业版和面试必备
4. **优化**（17–24 章）：进阶，等前三部分消化完再看
5. **Jev 专题**：对"结构化决策"感兴趣时单独看
