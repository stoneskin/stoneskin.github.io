# SAG2 导读：Jev 第一次有了实战——检索不用 embedding，靠一个只会判是非的小模型

> 详细摘要见 [sag2-summary.md](./sag2-summary.md)；本篇是导读（为什么值得看、主线、怎么读）。
> 引子是二手：袋鼠帝 @aikangarooking 2026-11-09 的 X Article《RAG这次真死了！SAG2才是本地知识库的神》，https://x.com/aikangarooking/status/2119717912546304048 。这篇转述有硬伤——它把 JEV 展开成“Junction Edge Value”，还给了一组跟论文对不上的数字（8.36%→61.48%），这两处都不要信，详见摘要第 6 节。

## 一句话结论

多跳检索不一定要先 embedding 整个语料库：SAG2 只在本地建一个 SQLite + BM25 词项索引，查的时候让 Jev（TypeSafe 的决策模型）一道一道判“这段是不是回答链里必需的证据”，判出来的好段再供词去扩下一轮——三轮下来，在三个多跳基准上 Recall@10 都拿了第一，索引 11,656 段只花 2.36 秒、25.87 MiB、零次模型调用。

## 为什么值得看

- **这是 Jev 第一次有了实战。** 10 月 21 日我们那份决策模型总结里，Jev 还是个“品类开创者”——知道它是什么、多少钱、多快，但没见过它在一个真实系统里到底干什么活。SAG2 就是那第一个公开答案：它不当评委、不当路由，当检索循环里的证据裁判。读这篇，等于把“决策模型”从概念变成了用法。
- **跟 open-memex 直接相关。** 你的记忆系统最头疼的就是同一件事：知识越攒越多，embedding 和向量库越跑越重，跨文档的多跳问题（“A 的 B 的 C 是什么”）最容易断链。SAG2 的答案是把准备工作压到最薄——不预建图谱、不算向量，连接在查询时才动态发生。这正是 open-memex 想走的方向，论文 §5.5 还留了一个口子：以后可以把 SAG 的实体抽取加回来，跟轻量架构取舍着用。
- **它是 RAG 的第三条路，不是改良版。** dense 检索是“先算好向量再比相似”，GraphRAG 是“先抽实体建好图再走图”，SAG2 是“什么都不预建，查的时候现找现连”。三条路的取舍点不一样，读完这篇，你对检索的选型就有了三选一的坐标，而不是只在“向量库选哪个”里打转。
- **便宜得可疑，但数据是硬的。** 1000 道题的评测只要 4.33 美元 Jev 调用费（§5.4），比起给整个语料库算 embedding，这便宜了一个量级。便宜本身不值得看，值得看的是便宜的同时 Recall@10 还赢了 NV-Embed-v2、GritLM-7B、HippoRAG 2 和它自己的前身 SAG——“快准便宜”三样里，它至少在基准上三样都占了。

## 叙事主线

1. 瓶颈：一个问题要的证据散在好几段里，中间那段跟问题本身没什么字面关系——比如先知道出生地，才能知道它属于哪个县。只按相似度排序的检索，中间这段永远排不上来，多跳就断在这里。
2. 前身的代价：作者自己的上一代 SAG（2026-06）解决了断链，用 LLM 先把每段抽成事件和实体，查询时用 SQL join 把共享实体的事件连起来。但代价是上线前就要对全库做语义抽取和 embedding，MySQL + Elasticsearch 两套库伺候着。
3. 换一个分工：SAG2 问，能不能把语义判断整个挪到查询时？本地只留词项索引（SQLite FTS5 + BM25），语义的事交给一个只会判是非的小模型 Jev。Jev 不写推理、不生成文本，只对每段回一个 0–1 的概率：“这段是不是必需的证据”。
4. 循环长这样：BM25 先捞 100 个候选 → Jev 逐个打分 → 分数最高的前 10 段当种子，从它们正文里挑 20 个词 → 用这些词再 BM25 捞一轮新的 → Jev 带着已捡到的证据再判一轮。最多扩两轮，每道题最多判 340 次。
5. 结果：三轮下来，MuSiQue Recall@10 从 BM25 的 54.41% 涨到 86.62%，2WikiMultiHopQA 到 97.43%，HotpotQA 到 99.00%，都超过了 SAG 和所有 dense 基线；但四跳题的完整证据覆盖率只有 28.31%，语义类问题在企业基准上也只有 58.40%——长链和纯语义，仍是它的短板。

## 怎么读（分级）

- 【对照正文】——§3.2–§3.5 检索流程：这是全文的骨架。重点看 Jev 那道题是怎么问的（“是不是必需事实，含中间识别事实”）、种子怎么挑、扩词的权重公式里四项各是什么意思。不用抠公式推导，抓住“分数怎么影响下一轮”就行。

## 跟你的咬合

- **open-memex**：最直接。SAG2 的“查询时动态连接”跟 Karpathy LLM Wiki 的“一次编译进 wiki”是同一问题的两个答案：一个主张现算现连、一个主张预先编译。你的系统里，热记忆走哪条、冷记忆走哪条，读完这篇再定，比只看一篇定更有底。另注意：SAG2 的索引是本地的，但 Jev 判断要把问题和候选段发给 hosted 服务——这跟 open-memex “local-first 即边界”的立场有张力，摘要第 7 节展开了。
- **thinktank 的 judge 层**：决策模型总结里留的演进方向（“成员出意见 + 决策模型出概率做加权与熔断”）在这里有了现成范式：Jev 不是在最后给总分，而是在循环中间每一步给概率、决定下一步往哪走。评审聚合也可以借这个“中间裁判”的位置。
- **学习地图里的定位**：组二记忆与检索进阶的新成员。合读三份：决策模型与 Jev（组一，Jev 本体）、Karpathy《LLM Wiki》（第 49 份，编译式记忆的另一极）、Agentic RAG（检索→评估→重试的循环，SAG2 是同一循环在证据层的实现）。
