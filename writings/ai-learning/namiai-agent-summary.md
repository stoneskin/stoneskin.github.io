> 一句话：中文动手系列——从 100 行循环亲手搭出一个完整 Agent，配可运行代码（到 EP11 共 49 个测试），再拿 11 个零件当尺子拆 7 个主流 Agent；Gulli 那本是模式教材，这份是“亲手搭一遍”的对照。
> 诚实标注：作者背景页面未载，不知名来源；拆解篇里闭源产品（Claude Code 内部、Grok Bot）的部分说法是公开资料推断，按二手假设对待，不当定论。

- **结构**：三部分——第一部分手写核心（EP01–07：最小循环、工具系统、权限、上下文管理、Skills、接入聊天软件、定时任务与心跳）；第二部分补主流能力（EP08–11：MCP、子 Agent 与多 Agent、计划、记忆）；第三部分拆解主流 Agent（EP12–17：Claude Code、Codex、Pi、Grok Bot、DeepSeek Harness、OpenClaw 与 Hermes）+ EP18 总对照表。
- **设计主线（抽查 EP11、EP18 核实）**：记忆分三层（项目说明常驻 / 会话记录 / 长期记忆 + 会话检索），长期记忆 2000 字上限、会话开始时拍快照（保前缀缓存）、写入逐条确认、子 Agent 与定时任务写不了记忆——“记忆是一个持久的注入入口”；EP18 五条共识（同一循环、技能按需加载、MCP、上下文先便宜后贵、写操作不并行）与四条分歧（安全边界放哪、计划多正式、谁写记忆、模型绑不绑定），主线一句话：“模型只提请求，执行与否、执行多少、结果怎么回去，由代码决定。”
- **它补的缺口**：清单里动手材料此前只有 walkinglabs 一份（搭 harness）；这份是“搭 Agent 本体”的动手线，且带拆解对照——同一套零件既亲手写过、又拿去量主流产品。另补 Hermes 记忆设计（MEMORY.md/USER.md + 冻结快照 + 全文检索）这一参照点，与你每天用的助手形态同源，可对照着看。
- **它不补什么**：教学代码非生产硬化（EP18 自己也说，放进沙箱才是“敢在自己电脑上长期跑”的分界）；评测只到单测通过，没有 thinktank 的陪审校准与 Harness² 的 ablation 对比；企业治理与安全只到权限分级一层，不到 OWASP/NIST 那一侧。

### 跟你的咬合

- **WorkBuddy 最直接**：EP06 聊天接入 + EP07 定时/心跳 + EP03 权限 + EP11 记忆，基本就是 WorkBuddy 的骨架；配套代码可当 M0 实验的参照实现，先跑起来再信。
- **open-memex**：EP11 是现成的设计参照与红队材料——快照、限额、确认制、关键词检索 vs 向量检索；Hermes 选自动写、它选逐条确认的取舍，正好是你 capture 规则要定夺的点。
- **thinktank**：EP09 子 Agent（并行只读、一层）+ EP10 计划（代码强制只读）对应 panel/陪审设计；“写操作不并行”那条共识直接管评审轮次怎么排。
- **muse-agent-harness**：EP05 技能只读 + AGENTS.md 分层，与规则导出思路同源；model-fuse 关系最弱，只有 EP02 工具注册表与 EP08 MCP 客户端能借鉴路由/注册思路。
- 三个关键问题：EP03 硬规则 + 分级 + 确认，拿到 WorkBuddy 的审批门怎么定、确认疲劳拿什么解 / EP11 逐条确认 vs Hermes 自动写，open-memex 的 capture 规则站哪边 / EP18 四条分歧里安全边界放“问人”还是“沙箱”，你的 harness 选哪层硬边界。
